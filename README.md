<h1 align="center">Obol Docs</h1>

This repository is the [Docusaurus](https://docusaurus.io/) source for the Obol
documentation site (docs.obol.org). **Documentation is authored here** — the
content was imported once from the retired GitBook space
([ObolNetwork/obol-gitbook](https://github.com/ObolNetwork/obol-gitbook)) with
URL slugs that exactly match the old GitBook URLs, so no public link broke in
the move. Edit pages under `docs/` (next) and `versioned_docs/` (released
versions) directly.

## Quickstart

Requires Node >= 20 (CI builds on Node 22) and Yarn v1.

```shell
yarn install     # install dependencies
yarn start       # local dev server with hot reload at http://localhost:3000
yarn build       # generate the static site into ./build
yarn typecheck   # run tsc against the site config and components
```

## Versions and URL scheme

- **The latest release** (first entry in `versions.json`, currently v1.10) is
  served at the **site root** (`/learn/...`, `/run-a-dv/...`) so URLs match
  the links already indexed and shared for docs.obol.org.
- **next** — the in-development docs in `docs/`, served under **`/next/...`**
  (noindexed, "unreleased" banner).
- Older releases stay reachable at `/<version>/...` with an "unmaintained"
  banner.

### Cutting a new version

Run the **"Cut a docs version"** GitHub Action (workflow_dispatch, e.g. with
`v1.11`), or locally:

```shell
yarn docusaurus docs:version v1.11
```

This snapshots `docs/` into `versioned_docs/version-v1.11/`. The newest entry
in `versions.json` is automatically served at the site root — no config edit
needed. Note that moving the previous version off the root changes its URLs
(`/learn/...` → `/v1.10/learn/...`), which is the standard Docusaurus scheme.

## Editing content

Docs are plain Markdown (`.md`, parsed as CommonMark) or MDX (`.mdx`, used
where pages need `<Tabs>` or React components such as `ApiEndpoint`).
Conventions:

- Each page's `slug:` frontmatter pins its public URL — don't change slugs
  without adding a redirect.
- Custom heading anchors use `### Heading {#anchor-id}`; keep existing ids so
  deep links keep working.
- Sidebars are explicit: `sidebars.js` (next) and
  `versioned_sidebars/version-*.json`. Add new pages there.
- Images live in `static/img/`.
- The API reference at `/api` renders `static/openapi/obol-api.json`; refresh
  it with `node scripts/update-api-spec.mjs`.

## Deployment: preview vs production

Deployment is automated with GitHub Actions:

- **`.github/workflows/deploy.yml`** — on push to `main`, builds and publishes
  `./build` to GitHub Pages in **production mode**: `baseUrl: /` for
  `https://docs.obol.org`, with the `CNAME` shipped from `static-prod/`.
  DNS for docs.obol.org must point at GitHub Pages for this repo. To publish
  a shareable preview at `https://obolnetwork.github.io/obol-docs/` instead
  (`baseUrl: /obol-docs/`, no `CNAME`), set `DEPLOY_PREVIEW: "true"` in the
  workflow's `env`.
- **`.github/workflows/test-deploy.yml`** — on every pull request to `main`,
  runs `yarn typecheck` and `yarn build`.
- **`.github/workflows/release.yml`** — manual "Cut a docs version" workflow;
  snapshots `docs/` as a new version and opens a PR.

Local preview-mode build: `DEPLOY_PREVIEW=true yarn build`.

## Redirects for legacy paths

`scripts/generated/redirects.json` (~1,200 entries, loaded by
[`@docusaurus/plugin-client-redirects`](https://docusaurus.io/docs/api/plugins/@docusaurus/plugin-client-redirects))
maps every legacy URL generation to the current routes: the pre-2024
`/docs/...` era, the previous Docusaurus era (`/learn|run|adv|gov/...`), and
all old version-prefixed paths (`/v0.16.0/...`). If you move a page, add an
entry there.

## LLM-friendly output

Every build emits machine-readable copies of the docs alongside the HTML:

- `/llms.txt` — an index of every page with descriptions.
- `/llms-full.txt` — the full current-version corpus in one file.
- a raw `.md` file for every documentation route (append `.md` to any page
  URL).

These are generated by the local plugin in `plugins/llms-txt/`, driven by the
sidebars and page frontmatter, so they stay correct as content evolves.

## History: the GitBook import

`scripts/migrate-gitbook.mjs` (`yarn migrate`) performed the one-time import
from the obol-gitbook repo: it converted GitBook-flavoured markdown (hints,
tabs, OpenAPI blocks, card tables, figures, explicit heading anchors) to
Docusaurus markdown/MDX, derived slugs from the live site's `llms.txt`,
generated sidebars from `SUMMARY.md`, and normalized assets. It is kept for
reference and for re-importing a branch if ever needed:

```shell
node scripts/migrate-gitbook.mjs \
  --source <obol-gitbook-worktree> --version next \
  --llms <llms.txt> --llms-section "Next" \
  --out docs --sidebar sidebars.js
```

⚠️ Re-running it **overwrites** the target docs directory, discarding any
edits made here since the import.
